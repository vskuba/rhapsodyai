# Event — события и подписчики

> Асинхронный pub/sub: код вызова шлёт событие, обработчики выполняют его
> параллельно и независимо. Обработка ошибок не роняет вызывающий код.
> Ядро: `py_modules/event_/event_.py`, обработчики — `src/event/event_handlers.py`.

## 1. Ядро

Три функции в `py_modules/event_/event_.py`:

| Функция | Что делает |
|---------|-----------|
| `event_subscribe(type, handler)` | регистрирует handler на тип; `_subscribers` — `dict[str, list]` |
| `event_emit(type, payload)` | создаёт `Event`, для каждого handler запускает `asyncio.create_task(_event_handler_run)` |
| `_event_handler_run(handler, event)` | обёртка: `await handler(event)` + `try/except` с логом |

`Event` — dataclass `type: str`, `payload: dict`. Подписчики не получают
результат друг друга: каждый — отдельная задача.

## 2. Обработчики `user.login`

Регистрируются в `event_handlers_register()` (вызывается из
`main_uvicorn.py` при старте). Сейчас два:

* `_event_log_persist` — кладёт событие в `event_log` (`type='system'`,
  `payload` = `json` с дописанным `event_type`).
* `_telegram_notify_login` — шлёт `telegram_send_owner(...)` владельцу, но
  **пропускает** полноправные роли (`auth_role_is_full(role)`) — `admin` и `qa`
  логируются постоянно, уведомления только шум.

Источник: `event_emit('user.login', {'user_id', 'username', 'role'})` в
`src/uvicorn/routers/auth/auth.py:87`.

## 3. ⚠ `event_emit` не ждёт обработчиков

`asyncio.create_task` — «fire and forget». Вызвал `event_emit` — запрос
вернулся сразу, обработчики выполняются в фоне. Последствия:

1. **Порядок не гарантируется.** Если два события пойдут подряд, второй может
   завершиться раньше первого.
2. **Ошибки обработчика не видны вызывающему.** Пойманы в
   `_event_handler_run`, пишутся в лог — и всё. Событие считается «отправленным»,
   даже если один из обработчиков упал.
3. **Счётчик задач растёт.** Каждый `event_emit` добавляет задачи; при
   интенсивности это нагрузка на event loop, но не блокировка.

❌ Ждать, что `event_emit` гарантирует доставку или порядок.

✅ Для критичных сценариев — `await` напрямую, не через события.

## 4. Как добавить обработчик

```python
async def my_handler(event: Event):
    ...

event_subscribe('user.login', my_handler)
```

Регистрация — в `event_handlers_register()` (или там, где инициализируется
подсистема). Дублировать регистрацию не надо: `event_subscribe` добавляет,
`event_emit` обходит список, дублирующий вызов — дублирующая работа.

## Грабли

1. **Ожидать синхронности** — §3, `event_emit` вернётся раньше, чем обработчики
   закончат.
2. **Думать, что ошибка обработчика падает** — §3, она в лог, вызывающий код не
   знает.
3. **Считать, что `payload` неизменяемый** — §1, `dict`, любой обработчик может
   его мутировать; другие подписчики получат изменённый словарь.
