# STT — расшифровка речи для соседних проектов

> Модель Whisper живёт здесь, голос присылает **BlogAi** («Блокнот»): человек
> диктует мысль в Telegram-приложение, текст становится черновиком.
> Код: `src/uvicorn/routers/stt/stt.py`, движок — `src/faster_whisper/`.

## 1. Две точки, и это не дублирование

| Точка | Модель | Когда | Зачем |
|-------|--------|-------|-------|
| `POST /api/stt/chunk` | `base` | пока человек говорит | живой текст на экран |
| `POST /api/stt/final` | `small` | когда закончил | текст черновика |

Обе требуют право `stt:create` (учётка `blog_service`, см. `auth.md`), принимают
`multipart/form-data` с полем `file` и необязательным `language` (по умолчанию
`ru`).

Существующий `/telegram-app/chat/voice` **не тронут**: он берёт файл целиком и
работает.

## 2. Почему модели разные — замеры

Замер 20.08.2026 на 26.6 с русской речи с известным эталоном (материал
синтезированный, поэтому числа — ориентир, а не закон):

| Модель | Целиком | Чанки 5 с | Успевает за речью |
|--------|--------:|----------:|-------------------|
| `base` | 20.5% ошибок | 26.0% | да, 3.2 с на чанк |
| `small` | **16.4%** | 34.2% | **нет**, 7.0 с на чанк |

Вывод, который выглядит противоречиво: **модель побольше делает целый файл
лучше, а нарезанный — заметно хуже.** Причина в контексте: чанки его рвут, а
большая модель на него сильнее опирается.

Отсюда разделение. `/chunk` показывает человеку, что запись идёт и о чём она —
26% ошибок для этого достаточно. `/final` считает то, что сохранится.

⚠ **Склеивать ответы `/chunk` и сохранять нельзя** — результат на десять пунктов
хуже, чем один проход `/final` по целому файлу.

## 3. Настройки внутри

`faster_whisper_transcribe()` получил параметры `model_name`, `language`,
`beam_size`; умолчания прежние, старые вызовы работают как работали.

* **язык задаётся явно** (`ru`): автоопределение гоняет модель по началу каждого
  чанка заново — замер показал 39% потери времени даром;
* **`beam_size=5` и для чанков.** `beam=1` вдвое быстрее, но ломает слова
  («записываю **мой соброновый** формат» вместо «мысль про новый») — для показа
  терпимо, для сохранения нет, а разделять настройки ради этого не стоит;
* **VAD не выключен**, хотя и стоит полсекунды: без него Whisper галлюцинирует
  на тишине артефакты вроде «You» и «Thank you» — про это предупреждает
  комментарий в `faster_whisper_model.py`.

## 4. Временный файл на каждый запрос

faster-whisper принимает путь, а не байты, поэтому загруженное кладётся на диск.
**В `tempfile.mkstemp()`, а не в рабочую папку:** `/telegram-app/chat/voice`
собирает имя из имени загруженного файла, и это безопасно только потому, что
звонящий там один. Сюда же за одну запись прилетают десятки чанков, в том числе
параллельно.

Файл удаляется в `finally` — упавшая расшифровка не должна оставлять мусор.

## 5. Проверка

```bash
TOKEN=<токен учётки blog_service>
curl -s -X POST localhost:8011/api/stt/chunk -H "X-API-KEY: $TOKEN" -F file=@chunk.wav
curl -s -X POST localhost:8011/api/stt/final -H "X-API-KEY: $TOKEN" -F file=@whole.wav
```

Проверено 20.08.2026: чанк 5 с → 3.9 с и верный текст; целый файл 26.6 с →
23.5 с и 72 слова; пустой файл → 422 «пустой файл»; без токена → 401; временные
файлы за собой убирает.

## Грабли

1. **Сохранять склейку чанков** — §2, она заметно хуже одного прохода.
2. **Ставить `small` на `/chunk`** — §2, станет и хуже, и медленнее речи.
3. **Убирать явный язык** — §3, даром теряется 39% скорости.
4. **Выключать VAD ради скорости** — §3, вернутся галлюцинации на тишине.
5. **Собирать имя временного файла из имени загруженного** — §4, чанки летят
   параллельно и передерутся за имя.

# Агент разметки черновиков (`/api/blog/tag`)

Нода `Blog`, агент `blog_tagger`, workflow из одного шага
`return_response_llm`. Точка принимает `{text, vocabulary}` и возвращает
`{tags, title}`.

## Почему словарь идёт в запросе

Без словаря агент размечает каждый черновик независимо, и через сотню записей
получаются «бизнес», «про бизнес», «бизнес-идеи» и «business» — четыре полки
вместо одной. Словарь идёт **первым** в промпте: модель сильнее держит начало
инструкции, а переиспользование — главное требование, не приписка.

## ⚠ Что проверено и где предел

Проверено 20.08.2026 на модели `gx10/qwen-small` (локальная llama):

| Случай | Результат |
|--------|-----------|
| словарь пуст, текст про видео | `видео`, `субтитры` — верно |
| в словаре «видео», текст про «видеоролики» | **переиспользовал «видео»** — верно |
| в словаре нет подходящего (текст про бронирование жилья) | **2 из 3 прогонов «бизнес», 1 пусто** — неверно |

**Переиспользование работает, заведение нового тега — нет.** Когда в словаре нет
подходящего, модель либо натягивает чужой тег, либо не отвечает; правильного
(«отпуск», «поездки») не дала ни разу из трёх.

Промпт правился дважды: сначала он слишком поощрял переиспользование, потом
слишком его ограничил — и модель стала возвращать пусто. Устойчивого равновесия
на этой модели добиться не удалось.

Отсюда два следствия, и оба обязательны:

1. **Теги должны править руками** — в BlogAi есть переименование и слияние
   (`blog_tags.py`). Разметка агентом это черновик разметки, а не приговор;
2. **Модель побольше, вероятно, справится лучше.** Задача требует суждения
   «подходит ли этот тег по смыслу», и локальная маленькая llama на нём плывёт.
   Проверять на другой LLM — отдельная задача, числа выше снимать заново.

## Грабли

1. **Шаг `llm_to_json` вместо `return_response_llm`** — первый раскладывает
   ответ по переменным workflow и наружу НЕ возвращает ничего. Разметка молча
   приходила пустой.
2. **`companion_id` из телеграмных констант** — там 3, а в этой установке
   собеседника с таким id нет, и запись в `agent_session` падает на внешнем
   ключе. Здесь 1 (`user_admin`).
3. **Верить, что агент сам поддержит чистый словарь** — не поддержит, см. выше.
