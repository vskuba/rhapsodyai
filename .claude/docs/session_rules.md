# Session Rules — разрешения Claude Code в этом проекте

Список того, что разрешено и что запрещено делать в рамках работы над RhapsodyAi, и при каких
условиях действует исключение. Без описания процессов/как делать — только права.

## ✅ Разрешено

| Действие                                                                                                       | Условие                                                                             |
|----------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| Developer-агент (`/loop`, автономный): commit + открытие PR в feature-ветку                                    | Всегда, как штатная часть работы агента над задачей                                 |
| QA-агент: создание записи-отчёта в очереди задач                                                               | Всегда — единственное разрешённое действие QA                                       |
| Ручное выполнение миграций/DDL на прод-БД (например `CREATE TABLE`, совпадающий с уже закоммиченной миграцией) | Всегда — авто-применение на деплое не гарантировано, ручное выполнение ожидаемо     |
| Отправка сообщений владельцу в Telegram (`telegram_send_owner`)                                                | Всегда, для прогресса/итогов задач — не требует отдельного разрешения на каждый раз |

## ❌ Запрещено

| Действие                                                                                                                                                         | Исключение (когда всё же разрешено)                                                                                    |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| `git commit` / `git push` в любую ветку от своего имени                                                                                                          | Явное разрешение пользователя в текущем чате, ИЛИ явная инструкция через Telegram (Mini App чат / сообщение боту)      |
| Developer-агент: push/merge в `main` (master)                                                                                                                    | Никогда автономно — только пользователь вручную                                                                        |
| QA-агент: правка кода, рестарт сервисов, любое изменение состояния прода                                                                                         | Никогда — QA только наблюдает                                                                                          |
| Правка `.env` / секретов на прод-сервере или в GitHub Secrets в любой форме (SSH-редактирование на месте, скачивание файла, запись через `gh secret set` и т.п.) | Только по явному разрешению пользователя на этот конкретный шаг в текущем разговоре — не переносится на будущие сессии |
| Вывод сырых значений секретов (пароли, токены, приватные ключи) в транскрипт/лог                                                                                 | Никогда — брать значения из окружения самого процесса/контейнера, не grep/cat `.env` с паролями                        |
| Массовые ad-hoc Python-скрипты с `mysql_pool_get()` против прода                                                                                                 | Только если гарантировано закрытие пула; для разовых запросов предпочитать `mysql` CLI напрямую                        |
