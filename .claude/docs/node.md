# Node — CRUD нод и их LLM

> Нода — логическая «группа» LLM-моделей: роутер CRUD-оперирует таблицами
> `node` и `node_llm`, страница `/admin/node` тянет отсюда данные.
> Код: `src/uvicorn/routers/node/node.py`, права — `NODE_*`.

## 1. Что такое нода

`node` — имя + порядок (`position`) + лимит параллельности
(`llm_parallel_per_agent_max`) + флаг `is_catchall`. Привязка моделей —
таблица `node_llm` (M:N с приоритетом). Как нода участвует в выборе модели и
фоллбэке при 429 — в `llm.md`.

## 2. Роуты

| Метод | Путь | Право | Результат |
|-------|------|-------|-----------|
| `GET` | `/node/list` | `NODE_VIEW` | все ноды, `name ASC` |
| `GET` | `/node/{node_id}` | `NODE_VIEW` | нода + `llm_ids` (порядок: `rate_limit_at ASC, position ASC`) |
| `POST` | `/node` | `NODE_CREATE` | новый `node_id`; `llm_ids` — в `node_llm` по порядку |
| `PUT` | `/node/{node_id}` | `NODE_UPDATE` | обновляет только переданные поля |
| `DELETE` | `/node/{node_id}` | `NODE_DELETE` | CASCADE по `node_llm` |

Ответы — `{result}` при успехе, `{status: "error", message}` при неудаче
(нет ноды на DELETE).

## 3. ⚠ `llm_ids` на PUT — полная замена

Если в теле `llm_ids` присутствует (даже пустой список) — старые строки
`node_llm` **удаляются** и перечисленные вставляются заново, `position`
собирается заново от 0. Если ключа нет — связь не трогается.

❌ Шлать `PUT` с частичным списком моделей, ожидая «добавить ещё».

✅ Шлать полный актуальный список; фронтенд `node.html` так и делает.

## 4. ⚠ `PUT` обновляет только `name` и `position`

Прочие поля тела (`is_catchall`, `llm_parallel_per_agent_max`) через этот
роут **не меняются**: `update_data` собирается только из этих двух ключей.
Для drag-and-drop достаточно — он шлёт только `position`.

❌ Думать, что лимит параллельности правится здесь.

✅ Править `is_catchall` / `llm_parallel_per_agent_max` — напрямую в БД
(`migrations/20260101000000_initial_schema.sql` — единственная точка схемы).

## 5. ⚠ `rate_limit_at` меняет порядок ответа

`GET /node/{id}` отдаёт `llm_ids` отсортированными по `rate_limit_at ASC,
position ASC`: модель, у которой недавно был 429, уходит **в конец**. Это
нормальное поведение маршрутизации (см. `llm.md`), но на странице «узлы»
список моделей после rate-limit будет отличаться от того, что вставлено.

❌ Сравнивать `llm_ids` с «тем, что было поставлено», без учёта
`rate_limit_at`.

## Грабли

1. **Частичный `llm_ids` на PUT** — §3, это замена, не добавление.
2. **Пытаться поменять `is_catchall` через API** — §4, роут не принимает;
   меняйте в БД.
3. **Удалять ноду, ожидая, что модели останутся** — §2, `node_llm` —
   `ON DELETE CASCADE`.
4. **Ждать `llm_ids` в `GET /node/list`** — §2, связь отдаёт только
   одиночный `GET /node/{id}`.
