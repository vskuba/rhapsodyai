# Translator — сканер каталога переведённых MD

> Перечисляет, какие переводы каких проектов лежат на диске: обходит
> `data_dir/MD_DIR/<проект>/<язык>/` и возвращает пары «проект — язык».
> Код: `src/translator/translator_md.py`.

## 1. Что это и зачем

Модуль не переводит. Он отвечает на вопрос «какие языки уже есть для этого
проекта», чтобы фронтенд мог показать список доступных переводов и кнопку
переключателя.

* Корень — `config_get('data_dir') + '/' + config_get('MD_DIR')`
  (ключи `DATA_DIR` и `MD_DIR` в `.env`, значения не в этом файле).
* Каждое поддерево второго уровня — один `TranslatorMd(project_name, language)`.
* Каталог может не существовать — тогда возвращается `[]`, не ошибка.
* Результат отсортирован по `(project_name, language)`.

## 2. Структура каталога

```
<data_dir>/<MD_DIR>/
├── rhapsody/
│   ├── en/
│   │   └── home.md
│   └── de/
│       └── home.md
```

Имя папки первого уровня — `project_name`, второго — `language`. Файлы внутри
не читаются и не проверяются: модуль смотрит только на имена директорий.
Пустая папка `en/` тоже попадёт в список — наличие языка определяется
наличием папки, а не файла.

## 3. ⚠ Подсистема без вызовов

`translator_md_list()` сейчас **нигде не вызывается** — в `src/`, `src/tool/` и
`src/cronjob/` ссылок нет. Это задел под перевод контента на диске: когда
появится роутер или инструмент, которому нужен список, — функция готова.

❌ Держать её «потому что может пригодиться» без ссылки и без теста — так и
непонятно, работает ли она и не сгнила ли.

✅ Либо подключить (роутер/инструмент, который отдаёт `translator_md_list()`),
либо удалить вместе с каталогом `MD_DIR`.

## Грабли

1. **Считать, что модуль переводит** — §1, это только сканер каталога;
   перевода нет нигде в этом проекте.
2. **Опираться на содержимое файлов** — §2, список строится по именам папок;
   пустая языковая папка выдаётся как «перевод есть».
3. **Ждать ошибку при отсутствии каталога** — §1, вернётся пустой список;
   отсутствие переводов и отсутствие каталога неразличимы.
