# E2E — проверка интерфейса кадром и числами

> Страница «Тесты → E2E» (`/admin/e2e`). Прогон открывает страницу панели,
> снимает кадр, меряет названные области **числами из DOM**, рисует на кадре
> рамки проверенных областей и кладёт строку в `test_e2e`. Вердикт — число
> («правый край 1147 при вьюпорте 360»), а не мнение.
>
> Методика приёмки, на которой это стоит, — `.claude/docs-common/frontend_check_rules.md`.
> Общий каркас прогона — `py_modules/tests_e2e/` (едет во все проекты),
> случаи этой установки — `tests_e2e/*.yaml`.

## 1. Зачем

Вёрстку пишут, не видя её: модель отдаёт HTML и CSS, не получив ни одного кадра
обратно, и «выглядит правильно» у неё означает «синтаксис верный». Типовой
дефект такой страницы в исходнике не виден вовсе — колонка уехала на 3 px, текст
обрезан на полуслове, блок вылез за вьюпорт. До сих пор это находил человек,
открыв страницу.

⚠ Ошибки при этом нет ни одной: журнал (`/admin/journal`) чист, в консоли пусто.
Поэтому «Тесты» — своя группа меню, а не подвкладка «Логов»: там «что упало»,
здесь «что нарисовалось не так».

## 1.1 Случай — файл в `tests_e2e/`

```yaml
name: Трассы — нет ошибок за сегодня          # имя в списке на странице
description: Вкладка «Error». Стережёт, что за текущую дату нет записей.
page: /admin/workflow_trace
widths: [1440]
steps:                                        # привести страницу в нужное состояние
  - click: '.status-tab[data-status="error"]'
  - wait_for: 'return !document.querySelector("#runsList").textContent.includes("Загрузка")'
areas:                                        # ВЁРСТКА: где элемент и цел ли он
  - name: Лента запусков
    selector: '#runsList'
    rules: [видна, не_вылезла]
checks:                                       # СОДЕРЖИМОЕ: что страница показывает
  - name: ошибок за сегодня
    expect: 0
    js: |
      await window.loadTz();
      const today = window.fmtTz(new Date().toISOString()).slice(0, 10);
      return [...document.querySelectorAll('.run-card .run-meta')]
        .filter(m => m.textContent.trim().startsWith(today)).length;
```

⚠ `areas` и `checks` отвечают на разные вопросы, и оба нужны. Зелёная геометрия
у страницы, показывающей вчерашние данные, — это зелёный тест на сломанной
странице.

⚠⚠ `js` обязан вернуть **число**, а не «да/нет»: вердикт читается как «ожидали
0, получили 3». По булеву ответу нельзя сказать, насколько промах.

Правила областей сейчас: `видна`, `не_вылезла`, `не_обрезана`, `непустая`.
Набор открытый — новое правило это функция в `tests_e2e_rule.py` и строка в
`rules:`.

## 2. Устройство прогона

```
случай (YAML) → uvicorn_mirror('/admin/llm') → URL копии с кукой входа
                    ↓ по каждой ширине из случая
  web_drive_eval  → rect'ы областей + вьюпорт + clipped + консоль
  web_shot        → кадр этой ширины
  правила         → вердикт по каждой области, с числом
  image_hotspot_overlay → рамки: зелёная сошлась, красная нет
                    ↓
  строка в test_e2e, кадры в data/e2e/<run_uuid>/
```

**Копия страницы — `uvicorn_mirror`.** Панель отвечает своей страницей только
вошедшему; копия несёт куку входа и проксирует `/static/` и `/api/` на панель,
поэтому страница на ней живёт целиком, со своими запросами и данными.

⚠ **Зонд — `web_drive_eval` (CDP), а не `web_probe`.** Зонд `web_probe`
вставляется в *копию файла*, а страницу по адресу подменить нечем — по http он
не ставится вовсе и честно об этом говорит.

## 3. Голова в контейнере

Браузер в контейнере `uvicorn` есть — playwright ставит его при сборке
(`playwright install chromium-headless-shell`). Отсюда важное следствие:
**контейнер-браузер прогону не нужен**, а значит, не нужен и общий пул вкладок
на 25 мест. Запрет «автоматически — никогда» из `testing_browser.md` к E2E не
относится: он про тот пул и про живого Chromium рядом с человеком.

⚠⚠ Две грабли, обе чинились в слое и обе ломали прогон **молча**:

1. Бинаря нет в `PATH` — он лежит в `~/.cache/ms-playwright/`. `_find_browser()`
   теперь смотрит и туда.
2. **Под root Chrome не стартует без `--no-sandbox`, и не говорит об этом**:
   код возврата 0, `--dump-dom` отдаёт пустой stdout, `--screenshot` не пишет
   файла. Флаг ставит `web_shot_argv()` по `geteuid`.

## 4. Таблица `test_e2e`

Строка — на **тест × ширину**, а не на тест: сетка, собранная на широкой,
на мобильной даёт горизонтальный скролл, и это разные вердикты одного случая.

| Поле | Что |
|------|-----|
| `run_uuid` | один прогон = одна метка на всех своих строках |
| `name`, `description` | **копией** из YAML на момент прогона |
| `page`, `width` | что и в какой ширине снимали |
| `status` | `ok` / `fail` (дефект найден) / `error` (прогон не состоялся) |
| `area_json` | строка на область: имя, селектор, rect, правила, вердикт, число |
| `shot_path`, `shot_plain_path` | кадр с рамками и чистый, пути от `data/e2e/` |
| `console_json` | что страница сказала в консоль |

⚠ `error` отделён от `fail` намеренно: «тест не смог проверить» и «тест проверил
и нашёл дефект» требуют разных действий, а одним красным неразличимы.

⚠ Имя и описание лежат копией по той же причине, что `object_name` в
`agent_workflow_history`: вчерашний прогон обязан читаться вчерашними словами,
даже если случай переписали.

## 5. Кадры на диске

`data/e2e/<run_uuid>/`, в базе только путь. Отдаёт их `/api/e2e/shot/{row_id}`
под правом `e2e:view`.

⚠⚠ **Путь берётся из базы по номеру строки, а не из запроса.** Отдавать файл по
присланному пути нельзя ни с какой проверкой: `..%2f` и симлинк превращают
раздачу кадров в чтение любого файла контейнера.

⚠ **В имени файла — отпечаток имени случая, и убирать его нельзя.** Имена
случаев русские, латиницы в них нет: «Журнал — ошибки» и «Настройки установки»
оба сворачивались в одно имя файла, и второй случай молча затирал кадры
первого. Поймано на первом же прогоне: 12 файлов вместо 18.

## 6. Страница

Карточка — **тест**, внутри кадр на каждую ширину; вердикт карточки худший из её
ширин. Щелчок по кадру открывает его крупно и список областей: что проверено и
с каким числом.

⚠ Плитки подрезаны по высоте (`object-fit: cover`, верх кадра): пропорции трёх
ширин разные, и без подрезки ряд идёт ступенькой, а карточка вырастает на
полтора экрана. Целый кадр — по щелчку, там он в натуральную величину.

Две кнопки в панели, и подписи у обеих словами: «⟳ Обновить» перечитывает
список, «▶ Прогнать сейчас» заводит прогон. Раньше у первой был голый значок
`⟳`, и он читался как «прогнать заново».

## 6.1 Кнопка «Прогнать сейчас»

Работа уезжает в очередь `default` (контейнер `worker_task`), ручка отвечает
сразу. Прогон длится минуты — держать на нём обработчик запроса нельзя: браузер
оборвёт его по своему таймауту, а работа останется идти в осиротевшем
обработчике.

⚠ **Single-flight**: пока идёт один прогон, второй не заводится. Десять нажатий
иначе дают десять браузеров на одной машине, снимающих одни и те же страницы.
Ключ в Redis снимается по завершении, срок у него — страховка от убитого
воркера, иначе кнопка осталась бы запертой навсегда.

⚠ Состояние прогона страница спрашивает **и при заходе**, а не только после
нажатия: прогон живёт в очереди, его мог завести сосед или ночное расписание, а
страницу — перезагрузить посреди прогона.

## 6.2 ⚠⚠ Адрес панели: имя сервиса, а не `localhost`

Прогон идёт из **двух разных контейнеров**: из кронджоба (`uvicorn`) и из
очереди по кнопке (`worker_task`). В первом `localhost:8000` — это панель, во
втором — сам воркер. С `localhost` прогон по кнопке падал
`ConnectError: All connection attempts failed`, записывая `error` в каждую
строку, — при совершенно живой панели.

Умолчание — `http://uvicorn:8000`, разрешается из обоих. ⚠ На проде с Blue-Green
правильный адрес другой, `http://caddy:8090`: прямое имя контейнера переживает
только чётное число выкладок (`deploy.md`). Задаётся переменной
`E2E_PANEL_URL`.

## 7. ⚠⚠ Покой страницы: ждать признак, а не секунды

Первые прогоны дали **разные вердикты** на одной странице: таблица `/admin/llm`
на 768 в одном прогоне `fail` по «не_обрезана», в следующем — `ok`. Причина не в
вёрстке: страница добирает данные запросом, и зонд успевал к разному её
состоянию.

Отсюда шаг **`wait_for`** — условие, которое опрашивается до наступления:

```yaml
steps:
  - click: '.status-tab[data-status="error"]'
  - wait_for: |
      const list = document.querySelector('#runsList');
      return list && !list.textContent.includes('Загрузка');
    timeout: 15000
```

⚠ Соседний шаг `wait` просто спит, и им пользоваться **не надо**. Ожидание
временем на занятой машине не дожидается ленты, и «записей нет» читается как
«ошибок нет» — зелёный тест на непроверенной странице. Плавающий тест хуже
отсутствующего: он приучает не смотреть на красное. `wait` оставлен для пауз без
наблюдаемого признака (анимация), и в случаях его быть почти не должно.

## 7.1 ⚠⚠ Кадр снимается тем же прогоном, что и замер

Кадр берётся зондом (`tests_e2e_probe`, аргумент `shot`), а не отдельным вызовом
`web_shot`. Отдельный вызов — это второй запуск Chrome и вторая загрузка
страницы, то есть кадр **другого состояния**: случай нажимает вкладку «Error», а
на снимке остаётся та, с которой страница открылась.

Поймано глазами на первом же настоящем случае. Числа при этом были верные —
беда видна была только в кадре, и ровно поэтому правка вёрстки без снятого
кадра считается гипотезой.

## 8. Что где лежит

| Путь | Что |
|------|-----|
| `tests_e2e/*.yaml` | случаи этой установки: имя, описание, страница, ширины, шаги, области, проверки |
| `py_modules/tests_e2e/` | общий каркас прогона — во всех проектах один: `_case` (чтение YAML), `_probe` (зонд и кадр), `_rule` (вердикты), `_shot` (рамки), `_run` (случай × ширина) |
| `src/e2e/e2e_runner.py` | прогон всех случаев установки; браузер — в `asyncio.to_thread` |
| `src/cronjob/e2e_run.py` | точка входа Cronicle, раз в сутки |
| `src/worker/e2e_worker.py` | прогон по кнопке: очередь `default`, single-flight |
| `src/e2e/e2e.py` | таблица `test_e2e`: запись, чтение, чистка по числу прогонов |
| `src/e2e/e2e_shot.py` | кадры на диске: пути, раздача, уборка |
| `src/uvicorn/routers/e2e/e2e.py` | `/api/e2e/*`: прогоны, строки, кадр |
| `data/uvicorn/template/admin/e2e.html` | страница |
| `migrations/20261009124416_test_e2e.sql` | таблица |

Права: `e2e:view` — чтение (есть у всех не-админских ролей, как `journal:view`),
`e2e:run` — кнопка «Прогнать сейчас» (поднимает браузер, в набор по умолчанию не
входит), `e2e:delete` — уборка прогонов.
