# Blog — агенты «Блокнота» для BlogAi

> Черновики живут в BlogAi (соседний проект), агенты — здесь, под нодой `Blog`.
> BlogAi ходит сюда по HTTP за тегами, сборкой текста и похожими черновиками.
> Код: `src/uvicorn/routers/blog/blog.py`.

## 1. Почему своя точка, а не `/chat/ask`

BlogAi — сосед. Ему незачем знать про workflow, `session_uuid` и идентификаторы
агентов, которыми мы тут пользуемся. Общий `/chat/ask` отдаёт их наружу; сюда
BlogAi присылает текст и словарь, получает теги, и не видит механики. Та же
причина, что и у STT — там тоже отдельная точка.

Все девять точек под `prefix="/api/blog"` требуют право `stt:create` — то же
право, что у расшифровки, потому что это **одна и та же** учётка соседа,
делаящая **одну и ту же** работу: превращает надиктованное в черновик. Заводить
второе право ради второй точки того же сценария незачем.

| Точка | Агент | Что делает |
|-------|-------|-----------|
| `POST /tag` | `blog_tagger` | текст + словарь → `{tags, title}` |
| `POST /compose` | `blog_writer` | черновики → связный `{text}` |
| `POST /index` | — | кладёт черновик в векторный поиск |
| `POST /similar` | — | похожие по смыслу черновики |
| `POST /index/remove` | — | убирает черновик из поиска |
| `POST /merge` | `blog_merge` | две расшифровки → один `{text}` |
| `POST /topics` | `blog_topics` | черновики → темы документов |
| `POST /document` | `blog_document` | черновики темы → готовый документ |
| `POST /rewrite` | `blog_rewrite` | документ + все заметки → дополненный |

`/index`, `/similar`, `/index/remove` — это Qdrant, а не LLM; у них нет своего
агента.

## 2. Где что описано

Пять точек из таблицы уже разобраны подробно в `stt.md` — там же их грабли:

* `/tag` — `blog_tagger`, словарь как условие, «заведение нового тега не работает»;
* `/compose` — `blog_writer`, пронумерованные черновики, запрет дописывать выводы;
* `/index`, `/similar`, `/index/remove` — коллекция `blog_draft`, чистый косинус
  вместо RRF, многоязычная эмбеддинг-модель, порог `BLOG_SIMILAR_MIN_SCORE`.

Здесь описаны только четыре «сборочные» точки (`/merge`, `/topics`, `/document`,
`/rewrite`), которых в `stt.md` нет, плюс то, что общее для всех девяти: константы
и путь вызова `_agent_ask`.

## 3. Константы

| Константа | Значение | Зачем |
|-----------|:--------:|-------|
| `BLOG_COLLECTION` | `blog_draft` | своя коллекция Qdrant, не общая с фактами |
| `BLOG_SIMILAR_MIN_SCORE` | `0.40` | порог «похожести»; ниже — связи нет (см. `stt.md`) |
| `BLOG_USER_ID` | `1` | от чьего имени идёт запрос — учётка владельца |
| `BLOG_COMPANION_ID` | `1` | **не 3** как в телеграмных константах — см. §5 |
| `BLOG_VOCABULARY_MAX` | `120` | сколько тегов словаря показать агенту |

Таймауты по агентам — в `_agent_ask` по имени агента, не одна на всех:

| Агент | Таймаут | Почему дольше/короче |
|-------|:-------:|---------------------|
| `blog_tagger` | 60 с | черновик короткий, подбирает слова |
| `blog_writer` | 180 с | пишет абзацы |
| `blog_merge` | 180 с | переписывает целиком, но работы меньше сборки |
| `blog_topics` | 240 с | читает десяток черновиков |
| `blog_document` | 300 с | связный текст из всех черновиков темы |
| `blog_rewrite` | 420 с | **самый объёмный вход**: все заметки + готовый документ |

Превышение таймаута → `504` и `future.cancel()` — сосед не должен висеть на
запросе.

## 4. Четыре сборочные точки

Все принимают черновики **пронумерованным списком** (не склеенной простынёй) и
возвращают `{"result": {...}}`. Пустой вход → `422`.

| Точка | Обязательное | Необязательное | Возврат |
|-------|-------------|----------------|---------|
| `/merge` | `chunked`, `full` | — | `{text}` |
| `/topics` | `drafts` (≥ 2) | — | список тем |
| `/document` | `title`, `drafts` | — | `{title, text}` |
| `/rewrite` | `title`, `current` | `drafts` | `{title, text}` |

### `/merge` — две расшифровки одной записи

Обе версии машинные и обе с ошибками, но ошибки **разные**: чанковая врёт на
стыках пятисекундных кусков, целая — теряет отдельные слова. Там, где они
расходятся, модель выбирает чтение, осмысленное в предложении. Обе обязательны:
с одной сводить нечего — выбор делается именно из расхождений.

### `/topics` — догадки, а не решения

Возвращает, о каких документах можно собрать текст. Решает ли человек собирать
— за ним, поэтому **пустой список — нормальный ответ** и лучше натянутых тем.
Из одной заметки документ «уже есть» (это она сама) → `[]` без вызова модели.
Черновики нумеруются в промпте, и модель ссылается на номера: имена и заголовки
она путает, а число — нет. Разбор ответа — §6.

### `/document` — черновики темы в связный текст

Пронумерованные `[заметка N]` плюс `Тема документа: {title}`. Возвращает тот же
`title` и собранный `text`.

### `/rewrite` — дополнить готовый документ

Вход самый объёмный в роутере: `current` (готовый текст) **плюс все заметки**,
а не только те, из которых документ собран. Мысль, записанная позже, могла лечь
в эту тему, но в исходный набор не попала. Отбирать нужное — работа модели, ей
для этого и дают всё.

## 5. Общий путь вызова `_agent_ask`

Все LLM-точки (6 из 9) сходятся в `_agent_ask(agent_name, message)`. Он повторяет
`_telegram_agent_chat_ask`, но без телеграмных подробностей: сессия **одноразовая**
(`uuid.uuid4()` на каждый вызов), история не нужна — разметка и сборка не диалог.

Путь: агент ищется **по имени** в `AgentRepository` → `ai_workflow_load` →
`ai_llm_node_get(agent.node_id)` → `framework_model_create` +
`framework_workflow_run` → `asyncio.wait_for(future, timeout)` (§3).

* Агент ищется по `name`, не по `id`: переименование агента в `agent` — и точка
  падает с `500 «агент не найден»`.
* `companion_id=1` (`user_admin`), **не 3** как в телеграмных константах: там
  число из другой установки, и у нас запись в `agent_session` падала на внешнем
  ключе `fk_memory_companion` — собеседника с `id 3` в таблице нет. См. также
  грабли в `stt.md`.

## 6. Разбор ответа `/topics`

`/topics` — единственная точка, где ответ модели надо разобрать в структуру, и
единственная, где это ломается. Три приватные функции:

* **`_topics_parse`** — берёт кусок от первой `{` до последней `}` (модель
  оборачивает JSON в ` ```json ` и добавляет фразу до/после), пробует разобрать
  кандидатов `_json_candidates`, отбрасывает темы с неизвестными номерами
  черновиков (модель их иногда придумывает) и темы из одного черновика
  (`len(ids) < 2`).
* **`_json_candidates`** — модель регулярно ошибается в закрывающих скобках:
  `{"topics": [{…}]]}` вместо `{"topics": [{…}]}`. Наступили на это на проде —
  тема найдена правильно, разбор молча вернул пустой список, человек видел
  «тем нет». Поэтому кроме самого куска пробуем срезанный по балансу скобок
  хвост и по одной снятой закрывающей с конца (до 3 попыток).
* **`_reason_clean`** — в `reason` нужно короткое «о чём будет документ», а
  модель, несмотря на запрет, начинает с «Черновики 1, 18 и 42 …». Убираем слово
  **вместе** с номерами (иначе останутся висящие «1, 18 и 42 …»), затем висящий
  союз и двойные пробелы, режем по 255.

Общее для всех LLM-точек: **`_thinking_strip`** срезает ход мысли до `</think>`
и **`_dense_search`** (только `/similar`) — чистый косинус, не RRF. Обе уже
описаны в `stt.md`, здесь не повторяем.

## 7. Проверка

```bash
TOKEN=<токен учётки blog_service>
# /merge — нужны обе версии
curl -s -X POST localhost:8011/api/blog/merge -H "X-API-KEY: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"chunked":"…","full":"…"}'
# /topics — из одной заметки всегда []
curl -s -X POST localhost:8011/api/blog/topics -H "X-API-KEY: $TOKEN" \
  -H "Content-Type: application/json" -d '{"drafts":[{"id":1,"text":"…"}]}'
# без токена → 401, пустой обязательный вход → 422
```

## Грабли

1. **Одна точка на `/chat/ask` для BlogAi** — сосед увидит workflow,
   `session_uuid` и id агентов; нужна отдельная точка (§1).
2. **Таймаут один на всех** — `blog_rewrite` читает все заметки и документ,
   60 с разметки ему не хватит; таймаут по имени агента (§3).
3. **`companion_id=3` из телеграмных констант** — `id 3` в этой установке нет,
   запись в `agent_session` падает на `fk_memory_companion`; здесь 1 (§5).
4. **Искать агента по `id`** — точки завязаны на имя; переименование в `agent`
   ломает их молча, пока не прилетит запрос (§5).
5. **Разбирать JSON `/topics` целиком** — модель оборачивает ответ в ` ``` ` и
   ошибается в закрывающих скобках; без `_json_candidates` разбор молча пустой (§6).
6. **Делать `/merge` с одной расшифровкой** — сводить нечего, выбор делается из
   расхождений двух версий (§4).
