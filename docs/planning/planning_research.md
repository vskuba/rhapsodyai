# Агентный плейбук исследования рынка (фаза: market)

## Концепция

Этот документ — пошаговый плейбук для фазы **market** AI-планировщика. Каждая фаза содержит **конкретные действия**: поисковые запросы, сайты для обхода, данные для извлечения. Агент не отвечает из своих знаний — он ищет реальные примеры, собирает метрики и строит вывод на основе найденных данных.

**Предусловие:** фаза `analyze` уже выполнена — идея структурирована, аудитория и риски зафиксированы.

**Правило:** каждый факт должен иметь источник (URL + дата). Данные без источника — не данные.

## Фаза 1 — Поиск реальных примеров (Existence Check)

**Цель:** найти 5–15 реально существующих продуктов/сайтов/сервисов в этой нише и зафиксировать их с метриками.

**Действия агента:**

### Шаг 1.1 — Поисковые запросы в Google
Запустить WebSearch по каждому запросу (адаптировать `{ниша}` и `{регион}`):
```
{ниша} сайт {регион}
лучшие {ниша} {регион}
топ {ниша} {регион} {год}
{ниша} platform {регион} site:crunchbase.com
{ниша} {регион} -wikipedia
"{ниша}" "{регион}" review
```

Для англоязычного рынка добавить:
```
best {niche} {country/region} 2024
top {niche} platforms site:g2.com
{niche} market leaders {region}
```

### Шаг 1.2 — Поиск в каталогах и рейтингах
Для каждого релевантного источника выполнить WebFetch и извлечь список игроков:

| Источник | URL-шаблон | Что извлечь |
|----------|-----------|------------|
| G2 | `g2.com/categories/{category}` | Название, рейтинг, кол-во отзывов, цена |
| Capterra | `capterra.com/catalog/{category}` | Название, рейтинг, кол-во отзывов |
| Product Hunt | `producthunt.com/search?q={query}` | Название, upvotes, дата запуска |
| Crunchbase | WebSearch: `site:crunchbase.com {ниша} {регион}` | Компании, стадия, финансирование |
| App Store | WebSearch: `site:apps.apple.com {ниша}` | Рейтинг, кол-во отзывов |
| Play Store | WebSearch: `site:play.google.com {ниша}` | Рейтинг, кол-во установок |

### Шаг 1.3 — Получить метрики трафика для каждого найденного сайта
Для каждого домена из шага 1.1–1.2 выполнить WebSearch:
```
site:similarweb.com {domain}
"{domain}" traffic statistics
"{domain}" monthly visitors
```

Также WebFetch: `similarweb.com/website/{domain}/` — извлечь:
- Monthly visits (месячная аудитория)
- Global rank / Country rank
- Bounce rate
- Avg visit duration
- Traffic sources (organic, direct, referral, social, paid)

### Шаг 1.4 — Проверить популярность ниши через Google Trends
WebFetch: `trends.google.com/trends/explore?q={ключевые+слова}&geo={код страны}`

Ключевые слова взять из формулировки ниши. Зафиксировать:
- Тренд (растёт / падает / стабильно)
- Пиковые периоды
- Регионы с наибольшим интересом
- Похожие запросы (related queries) — там часто реальные названия конкурентов

**Выходной артефакт — таблица найденных игроков:**
```
| Название | URL | Регион | Monthly Visits | Global Rank | Источник данных | Дата |
|----------|-----|--------|---------------|-------------|-----------------|------|
| ...      | ... | ...    | ...           | ...         | ...             | ...  |
```

**✓ Переход на фазу 2:** найдено ≥ 5 реальных продуктов с трафиком. Если не найдено — пересмотреть формулировку запросов или признать нишу незанятой (это может быть хорошей новостью или плохой).

## Фаза 2 — Анализ трафика и позиции в поиске

**Цель:** понять, насколько ниша востребована и как игроки в ней видны в поиске.

**Действия агента:**

### Шаг 2.1 — Ключевые слова и SEO-анализ
Для каждого игрока из фазы 1 выполнить WebSearch:
```
site:semrush.com {domain} organic traffic
site:ahrefs.com {domain}
"{domain}" keywords ranking
```

Зафиксировать для каждого домена:
- Топ-5 ключевых слов по органике
- Примерный органический трафик
- Domain Rating / Authority

### Шаг 2.2 — Оценить спрос через ключевые слова
WebSearch для поиска объёма запросов:
```
"{ключевое слово ниши}" search volume
keyword planner "{ключевое слово}" monthly searches
site:wordstat.yandex.ru {ключевые слова}  ← для RU-рынка
```

Целевые метрики:
- Суммарный объём запросов по основным ключевым словам
- Конкуренция (низкая / средняя / высокая)
- CPC (цена клика в рекламе) — косвенный сигнал монетизации ниши

### Шаг 2.3 — Присутствие в соцсетях и сообществах
Для топ-3 игроков выполнить WebSearch:
```
"{название}" site:reddit.com
"{название}" site:twitter.com
"{домен}" followers Instagram OR LinkedIn
```

Зафиксировать:
- Кол-во подписчиков в соцсетях
- Активность / последние посты
- Тональность упоминаний в Reddit/форумах

**Выходной артефакт:**
```
Спрос по ключевым словам:
| Запрос | Объём/мес | Конкуренция | CPC | Тренд |
|--------|----------|------------|-----|-------|

Топ-игроки по SEO:
| Домен | Органический трафик | DR | Топ-ключевые слова |
|-------|--------------------|----|-------------------|
```

**✓ Переход на фазу 3:** понятно, есть ли поисковый спрос и кто его захватывает.

## Фаза 3 — Глубокий анализ конкурентов (по каждому игроку)

**Цель:** для топ 5–10 игроков собрать детальные данные по единой структуре.

**Действия агента — для каждого игрока:**

### Шаг 3.1 — Визит на сайт
WebFetch: главная страница + pricing page + about page.

Извлечь:
- Tagline (заголовок на главной)
- На кого направлен (кто целевой пользователь)
- Ключевые функции (из features / about)
- Тарифные планы и цены
- CTA (что предлагают сделать: попробовать / купить / связаться)

### Шаг 3.2 — Отзывы пользователей
WebFetch: страница продукта на G2 / Capterra / Trustpilot / App Store.

Извлечь:
- Средний рейтинг
- Кол-во отзывов
- Топ-3 плюса (что хвалят чаще всего)
- Топ-3 минуса (на что жалуются чаще всего)
- Характерные цитаты из отзывов

Поиск отзывов через WebSearch:
```
"{название}" review site:g2.com
"{название}" reviews site:capterra.com
"{название}" отзывы
"{название}" problems OR complaints OR issues
```

### Шаг 3.3 — Финансирование и масштаб
WebSearch:
```
"{название}" funding crunchbase
"{название}" revenue ARR
"{название}" customers OR users count
"{название}" raised million
```

WebFetch: `crunchbase.com/organization/{slug}` — если доступно.

Извлечь:
- Стадия (bootstrap / seed / series A / public)
- Сумма привлечённого финансирования
- Последний раунд (дата)
- Инвесторы
- Известная выручка или кол-во клиентов

### Шаг 3.4 — Технологический стек (опционально)
WebFetch: `builtwith.com/{domain}` или WebSearch `"{domain}" technology stack builtwith`

Извлечь: CMS, CRM, аналитика, рекламные пиксели — косвенно показывает зрелость компании.

**Выходной артефакт — карточка конкурента:**
```
## [Название]
URL: {url}
Основан: {год}, {страна}
Стадия: {bootstrap/seed/...}
Финансирование: ${X} от {инвесторы} ({дата})

Tagline: "{цитата с сайта}"
Целевой пользователь: {кто}
Ключевые функции: {список}

Тарифы:
- {план}: ${цена}/мес — {что включено}

Метрики:
- Monthly visits: {X}
- Global rank: #{N}
- G2 рейтинг: {X}/5 ({N} отзывов)

Хвалят: {топ-3}
Жалуются: {топ-3}

Цитата пользователя (позитив): "{..."
Цитата пользователя (негатив): "{..."
```

**✓ Переход на фазу 4:** заполнены карточки для ≥ 5 игроков с реальными данными.

## Фаза 4 — Анализ трендов через реальные данные

**Цель:** понять, растёт ли ниша или стагнирует — на основе реальных сигналов, не предположений.

**Действия агента:**

### Шаг 4.1 — Google Trends (обязательно)
WebFetch по каждому варианту ключевых слов:
```
trends.google.com/trends/explore?q={ключевые слова}&geo={регион}&date=today 5-y
```

Фиксировать:
- График интереса за 5 лет
- Сезонность
- Регионы с наибольшим ростом
- Related rising queries (новые запросы в нише)

### Шаг 4.2 — Инвестиционные сигналы
WebSearch:
```
"{ниша}" funding 2024 site:techcrunch.com
"{ниша}" raised site:crunchbase.com 2023 OR 2024
"{ниша}" venture capital trends
"{ниша}" market report 2024
```

Зафиксировать:
- Кол-во сделок за последние 12 месяцев
- Общая сумма инвестиций
- Есть ли крупные раунды (Series B+) — признак зрелости рынка

### Шаг 4.3 — Активность в сообществах
WebSearch:
```
"{ниша}" site:reddit.com/r/startups OR /r/entrepreneur
"{ниша}" Hacker News 2024
"{ниша}" Product Hunt 2024
```

WebFetch: результаты поиска HN: `hn.algolia.com/?q={ниша}&dateRange=pastYear`

Зафиксировать:
- Растёт ли активность обсуждений
- Какие проблемы обсуждают (боли рынка)
- Новые игроки, появившиеся за год

### Шаг 4.4 — Новостной фон
WebSearch:
```
"{ниша}" news 2024
"{ниша}" market growth 2024
"{ниша}" trends site:forbes.com OR site:techcrunch.com OR site:wired.com
```

**Выходной артефакт:**
```
Тренд Google Trends: [растёт / стабильно / падает]
- Пик интереса: {период}
- Регионы роста: {список}
- Сигнальные запросы: {related rising queries}

Инвестиционная активность (12 мес):
- Кол-во сделок: {N}
- Объём: ${X}
- Крупнейший раунд: {компания} ${X} ({дата})

Вывод: ниша [горячая / растущая / зрелая / угасающая]
Обоснование: {2-3 предложения со ссылками}
```

**✓ Переход на фазу 5:** есть данные о динамике рынка с источниками.

## Фаза 5 — Синтез: паттерны, пробелы, незанятые ниши

**Цель:** на основе собранных данных найти паттерны и пробелы — что есть у всех, чего не хватает, где есть место для нового игрока.

**Действия агента:**

### Шаг 5.1 — Матрица функций
Составить таблицу: игрок × функция, с отметками ✓/✗/частично.

Выделить:
- **Table Stakes** — функции у ≥80% игроков (без них нельзя выходить)
- **Дифференциаторы** — функции у ≤30% игроков
- **Отсутствующие** — что никто не делает (потенциальный gap)

### Шаг 5.2 — Карта позиционирования
Выбрать 2 оси, релевантные нише (например: цена vs. функциональность, или простота vs. мощность).
Разместить каждого игрока на карте.
Найти "пустые квадранты" — там никого нет.

### Шаг 5.3 — Агрегация жалоб
Собрать из карточек конкурентов (фаза 3) все "жалуются" колонки.

Найти повторяющиеся темы — это **unmet needs рынка**:
```
| Жалоба | Кол-во игроков с этой проблемой | Интенсивность |
|--------|--------------------------------|--------------|
| ...    | ...                            | ...          |
```

### Шаг 5.4 — Ценовые пробелы
Из тарифов конкурентов построить ценовую карту:
```
$0–10/мес: {кто}
$10–50/мес: {кто}
$50–200/мес: {кто}
$200+/мес: {кто}
Enterprise (цена по запросу): {кто}
```

Найти незанятые ценовые диапазоны.

### Шаг 5.5 — Незанятые географические ниши
Из данных SimilarWeb — откуда трафик у конкурентов?
Есть ли регионы, где никого нет?

WebSearch для проверки:
```
"{ниша}" {регион без покрытия} (на языке региона)
```

**Выходной артефакт:**
```
Table Stakes (обязательно строить): {список}
Дифференциаторы (отличиться можно через): {список}
Топ-5 жалоб на рынке: {список с кол-вом}
Ценовые пробелы: {диапазоны без игроков}
Географические пробелы: {регионы}
Потенциальный white space: {описание возможности}
```

**✓ Переход на фазу 6:** найден ≥1 white space с подтверждением из реальных данных.

## Фаза 6 — Анализ клиентов (через публичные данные)

**Цель:** понять реального покупателя — не через предположения, а через публичные источники.

**Действия агента:**

### Шаг 6.1 — Форумы и сообщества
WebSearch:
```
"{ниша}" site:reddit.com
"best {ниша}" site:reddit.com
"{проблему которую решает продукт}" site:reddit.com
"{ниша}" forum OR community
"{ниша}" Quora
```

WebFetch: топ-3 треда. Извлечь:
- Кто задаёт вопросы (роль, контекст)
- Какие проблемы описывают
- Какие решения уже попробовали и чем недовольны
- Что ищут (switching triggers)

### Шаг 6.2 — Job postings (косвенный сигнал)
WebSearch:
```
site:linkedin.com/jobs "{ниша}" OR "{ключевая роль}"
site:hh.ru "{ниша}" (для RU)
"{ниша}" вакансии 2024
```

Из вакансий извлечь: какие компании нанимают людей в этой нише, какие навыки требуются — это показывает, кто платит деньги.

### Шаг 6.3 — Отзывы в деталях
WebFetch: страницы отзывов на G2/Capterra для топ-2 игроков.

Из отзывов извлечь:
- Должность / роль рецензентов
- Размер компании рецензентов
- Индустрия
- "Почему переключились с предыдущего решения"
- "Что бы улучшили"

**Выходной артефакт:**
```
Кто покупает:
- Роль: {должности из отзывов и форумов}
- Размер компании: {SMB / mid / enterprise}
- Индустрия: {список}

Топ-5 болей (цитаты из форумов/отзывов):
1. "{цитата}" — источник: {URL}
2. ...

Switching triggers (почему меняют решение):
- {причина} — источник: {URL}

Jobs to Be Done:
- Главная задача: {что хотят сделать}
```

**✓ Переход на фазу 7:** есть реальные голоса пользователей с источниками.

**Цель:** понять реальные цены и бизнес-модели на рынке — из публичных данных.

**Действия агента:**

### Шаг 7.1 — Собрать все тарифы
Из фазы 3 (карточки конкурентов) агрегировать все тарифные планы.

Дополнительно WebFetch pricing-страниц игроков, которых не покрыли ранее.

### Шаг 7.2 — Поиск данных о выручке
WebSearch:
```
"{игрок}" ARR revenue
"{игрок}" annual recurring revenue
"{игрок}" $X million revenue
site:latka.com "{игрок}"
```

Latka.com — база SaaS-метрик. WebFetch: `getlatka.com/companies/{slug}` если доступно.

### Шаг 7.3 — Анализ рекламных расходов (косвенно)
Через CPC из ключевых слов (шаг 2.1) оценить:
- Если CPC высокий (>$5–10) — ниша монетизируется, игроки готовы платить за трафик

WebSearch:
```

Модели монетизации на рынке:

Диапазон цен SMB: ${X}–${Y}/мес
CPC в нише: ${X} (сигнал монетизации: высокий/средний/низкий)
Рекомендованная модель: {обоснование из данных}
```

**✓ Переход на фазу 8:** известны реальные цены и хотя бы 1–2 данных о выручке.

## Фаза 8 — Оценка возможности (TAM/SAM/SOM)

**Цель:** посчитать размер рынка снизу вверх — из реальных данных, не из аналитических отчётов.

**Действия агента:**

### Шаг 8.1 — Bottom-up расчёт
Формула: `Кол-во потенциальных клиентов × ARPU = SAM`

Кол-во клиентов — откуда взять:
- Статистика по кол-ву компаний в сегменте (WebSearch: `кол-во {тип компаний} в {регионе}`)
- Статистика регистраций бизнеса (для RU: WebSearch `site:rosstat.gov.ru статистика`)
- LinkedIn: `site:linkedin.com/company {индустрия} {регион}` — приблизительно
- Государственная статистика: WebFetch соответствующих страниц

### Шаг 8.2 — Top-down проверка
WebSearch:
```
"{ниша}" market size {год}
"{ниша}" TAM billion
"{ниша}" market report {год} site:statista.com
"{ниша}" market size site:grandviewresearch.com OR site:marketsandmarkets.com
```

WebFetch доступных страниц. Извлечь:
- Размер рынка ($X млрд)
- CAGR (темп роста)
- Горизонт прогноза

### Шаг 8.3 — Сценарии доли рынка
На основе трафика конкурентов (фаза 1–2) оценить:
- Суммарный трафик топ-10 игроков
- При конверсии X% → кол-во клиентов
- При ARPU $Y → ARR нишевого игрока

```
Conservative (0.5% рынка):  {N} клиентов × ${ARPU} = ${ARR}/год
Base (2% рынка):            {N} клиентов × ${ARPU} = ${ARR}/год
Optimistic (5% рынка):      {N} клиентов × ${ARPU} = ${ARR}/год
```

**Выходной артефакт:**
```
TAM: ${X} (источник: {URL}, дата: {дата})
SAM: ${X} (метод: bottom-up, {регион}, {сегмент})
SOM (3 года): ${X} (base-сценарий)

CAGR рынка: {X}%
Стадия рынка: emerging / growth / mature

Барьеры входа:
- Технические: {оценка}
- Дистрибуция: {оценка}
- Сетевые эффекты у конкурентов: {оценка}

Timing: {почему сейчас / почему не сейчас}
```

**✓ Переход на фазу 9:** TAM/SAM посчитаны с обоснованием метода и источников.

## Фаза 9 — Инвестиционное решение (Go/No-Go)

**Цель:** финальный синтез в структурированный вывод.

**Действия агента:**

### Шаг 9.1 — Финальная проверка Kill Assumptions
Для каждого критического допущения:
```
Допущение: {утверждение}
Как проверено: WebSearch/WebFetch {что искали}
```

### Шаг 9.2 — SWOT на основе данных
Каждый пункт SWOT — только из найденных данных, со ссылками:
- Strengths: что позволяет войти (gap, timing, уникальность)
- Weaknesses: чего не хватает (ресурсы, команда, опыт)
- Opportunities: white spaces из фазы 5
- Threats: барьеры из фазы 8, конкурентные рвы из фазы 3

### Шаг 9.3 — Минимальные эксперименты перед полным входом

- Что можно проверить за 2–4 недели и $0–500
- Какой результат = "идём дальше", какой = "стоп"

## Карта переходов

```
[0] Формулировка гипотезы
    ↓ WebSearch: найти реальные примеры
[1] Поиск реальных примеров → таблица с трафиком
    ↓ WebFetch SimilarWeb, WebSearch SEMrush
[2] Анализ трафика и SEO → спрос подтверждён/опровергнут
    ↓ WebFetch сайты + G2 + Crunchbase
[3] Глубокий анализ конкурентов → карточки с реальными данными
    ↓ WebFetch Google Trends, WebSearch funding
[4] Анализ трендов → рынок растёт/стагнирует
    ↓ Синтез таблиц из фаз 1–4
[5] Паттерны и пробелы → white space найден
    ↓ WebSearch Reddit/форумы, WebFetch G2-отзывы
[6] Анализ клиентов → реальные голоса с источниками
    ↓ WebFetch pricing pages, WebSearch ARR данные
[7] Анализ монетизации → реальные цены и модели
    ↓ Bottom-up расчёт + WebSearch market size
[8] Оценка возможности → TAM/SAM/SOM с источниками
    ↓ Синтез всех фаз
[9] Решение GO/NO-GO + Blueprint документ
```

## Правила качества (для агента)

1. **Каждый факт = источник.** Если URL нет — это мнение, не данные. Не включать в Blueprint.

2. **Реальный пример важнее оценки.** Один работающий сайт с 50k посетителей говорит больше, чем аналитический отчёт о рынке.

3. **Трафик врать не умеет.** SimilarWeb может ошибаться на 20–30%, но порядок цифр отражает реальность.

4. **Жалобы ценнее похвал.** В негативных отзывах — незакрытые потребности рынка.

5. **Незанятая ниша ≠ возможность.** Может быть незанята, потому что не работает. Проверь: есть ли поисковый спрос? Есть ли форумные обсуждения? Это тоже должно быть найдено, а не предположено.

6. **Google Trends — обязательно.** Без него нельзя понять направление рынка.

7. **Данные устаревают.** Фиксировать дату каждого источника. Данные старше 18 месяцев — перепроверять.
